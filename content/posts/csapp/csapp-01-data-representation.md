## 为什么 0.1 + 0.2 ≠ 0.3

在大多数语言里跑 `0.1 + 0.2` 会得到 `0.30000000000000004`。这不是 bug，是 IEEE 754 浮点数的必然结果。

0.1 在二进制下是无限循环小数，double（64 位）只能存 52 位尾数，存进去的那一刻就已经有误差了。

## 三种整数编码

| 编码 | 表示范围 | 说明 |
|---|---|---|
| 无符号 | 0 ~ 2ⁿ−1 | 直接二进制 |
| 反码 | 对称 | 历史遗留，有 ±0 |
| 补码 | −2ⁿ⁻¹ ~ 2ⁿ⁻¹−1 | 现代通用，只有唯一 0 |

补码的核心好处：**加法和减法用同一套电路**。`a - b` 直接算成 `a + (~b + 1)`。

## 溢出

补码加法溢出后结果会「绕回去」：

```
INT_MAX + 1 == INT_MIN   // UB in C
```

C 语言里这是未定义行为，编译器有权做任何假设。所以判断溢出不能用 `if (a + b < a)` 这种技巧。

## 浮点的三个特殊值

- **+0 / −0**：比较时相等，但 `1/+0 = +∞`，`1/−0 = −∞`
- **±∞**：溢出或除以零的结果
- **NaN**：`0/0`、`∞−∞`。关键性质：`NaN != NaN` 永远成立，所以判断要用 `x != x` 或 `isnan(x)`

## 小结

理解位级表示之后，很多「玄学 bug」都变得可解释了 —— 精度丢失、溢出回绕、NaN 传播，本质都是编码规则的直接推论。
