## 为什么还要看汇编

高级语言抽象掉了机器细节，但有两类问题绕不过去：

1. **崩溃**：段错误时栈回溯是一串地址，看不懂汇编就只能猜
2. **性能**：编译器到底有没有把循环优化掉，只有看汇编才知道

## 寄存器

x86-64 有 16 个通用寄存器，但只有 6 个能自由用于传参：

```
rdi, rsi, rdx, rcx, r8, r9   → 前 6 个整型/指针参数
xmm0 ~ xmm7                  → 浮点参数
rax                          → 返回值
```

第 7 个参数开始就必须走栈了。

## 栈帧布局

调用一个函数时，栈从高地址向低地址生长：

```
高地址
  ┌──────────────┐
  │  调用者的帧   │
  ├──────────────┤
  │  返回地址     │  ← call 指令自动压入
  ├──────────────┤
  │  保存的 rbp   │  ← push %rbp
  ├──────────────┤ ← rbp 指向这里
  │  局部变量     │
  │  溢出参数     │
  └──────────────┘ ← rsp
低地址
```

## 栈溢出的真正含义

缓冲区写超了，会先冲掉局部变量，然后是**保存的 rbp**，再是**返回地址**。返回地址被改写 → `ret` 跳转到攻击者指定的位置。这就是经典的 stack smashing。

现代防御：栈保护（canary）、ASLR、NX 位。编译时默认开启的 `-fstack-protector` 就是在返回地址前插一个随机值，函数返回时检查它有没有被改。

## 小结

看懂汇编不是为了手写汇编，而是为了在出问题时能读懂机器真正做了什么。
