## 一个反直觉的例子

同样是遍历 4096×4096 的二维数组，只是把内层循环的两个下标对调：

```c
// 快
for (i = 0; i < N; i++)
    for (j = 0; j < N; j++)
        sum += a[i][j];

// 慢 10 倍以上
for (i = 0; i < N; i++)
    for (j = 0; j < N; j++)
        sum += a[j][i];
```

原因只有一个：**数组按行存储，第一种写法是顺序访存**。

## 存储器层次

```
寄存器         ~1 cycle      几百字节
L1 cache      ~4 cycles      32 KB
L2 cache     ~12 cycles     256 KB
L3 cache     ~40 cycles       8 MB
主存        ~200 cycles      几十 GB
SSD       ~100,000 cycles      TB 级
```

每往下一层，延迟涨一个数量级。缓存的全部意义就是**让大部分访问停在上面几层**。

## 缓存行

缓存不是按字节加载的，是按**块**（通常 64 字节）整块搬。所以：

- 访问 `a[0]` 时，`a[0]` 到 `a[15]`（int）已经一起进缓存了
- 顺序访问 → 每 16 次访问只有 1 次真正读内存
- 跳跃访问 → 每次都可能 miss

## 局部性

- **时间局部性**：刚访问过的数据，很可能马上再被访问（循环变量）
- **空间局部性**：访问了地址 x，很可能马上访问 x+1（数组遍历）

写代码时把这两条放在心上，性能收益往往比换算法还大。

## 实践清单

1. 循环顺序和内存布局对齐（行优先语言就按行遍历）
2. 小数据结构优先用连续数组，而不是链表
3. 分块（blocking）让工作集塞进 L1/L2
4. 警惕 false sharing：多线程写同一缓存行的不同变量，会互相踩

## 小结

现代 CPU 和内存的速度差距有 200 倍以上。写出缓存友好的代码，是把硬件潜力发挥出来的前提。
